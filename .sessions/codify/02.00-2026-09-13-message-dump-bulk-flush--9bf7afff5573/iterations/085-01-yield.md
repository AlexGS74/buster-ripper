## Pass 1 — code reasoning, and what it disproved

Written from the two repo files and the installed library bytes, before Forward's report was read. Three serious
candidates were chased and closed with source, not with the author's word:

1. **`result.text` can return `None` → `TypeError` inside the probe.** `web_response.py:724-730` returns `None` when
   `_body is None`, and `parse_context_overflow_error` is typed `error_text: str` (`utils.py:123`). Not reachable:
   both objects the loop can be handed always set `_body` — `:162` passes a `str` (even the empty string reaches
   `StringPayload`, which I executed to `.text == ''`, not `None`), and `:184`'s `json_response` takes the constructor's
   `text=` fast path, which encodes bytes onto `_body`. The `isinstance(result, web.Response)` guard at `:105` excludes
   the third shape (a prepared `StreamResponse` has no `.text` at all). Executed on 3.13.3, so this is measurement.
2. **A strict decode can raise out of `handle_streaming`.** `Payload.decode` defaults to `errors="strict"`, and the
   promoted claim record at `invariants/buster_ripper/assumption-claims.md:3281` states the escape hatch plainly: a
   `Content-Type` naming a non-utf-8 charset makes `.text` decode with a codec the payload was not encoded with.
   Not constructible at this site — the producer hard-codes `content_type="application/json"`, which names no charset,
   so `.charset` is `None` and the fallback is the codec `StringPayload.__init__` encoded at. Executed: `r.charset`
   `None`, `Content-Type: application/json`, `r.text == input` → `True`.
3. **The now-live re-dispatch could carry a stale `Content-Length`** — the one hypothesis that would have been a
   genuine new defect, because the mutated body only ever reaches the wire now that the loop fires. Closed on two
   bytes: `utils.forward_headers` drops `content-length` (`utils.py:25`), and `ClientRequest.update_headers` builds a
   **fresh** `CIMultiDict` per request (`client_reqrep.py:1056-1058`) before `update_body_from_data` derives the
   length from *that* call's payload (`:1199-1201`). The dict `handle_streaming` reuses cannot accumulate a length
   across attempts.

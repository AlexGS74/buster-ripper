## 5. New fact raised by this increment, recorded not decided

This pass adds `from multidict import CIMultiDict, CIMultiDictProxy` to
`buster_ripper/utils.py`. `multidict` is a *transitive* dependency (aiohttp hard-requires it;
`pyproject.toml` declares only `aiohttp` + `click`), already imported in
`tests/upstream_stub.py:15` and `tests/test_header_parity.py:24`, and named by the plan's own
closure (`DC-S15-CE-2-r1`: "a `CIMultiDict`, or the pairs themselves") and by `RB-002`/`RB-004`'s
"Deps stay aiohttp + click" — which says no new *install*, and none is added here.

Whether a direct import should now be declared is a dependency-manifest decision outside this
wave's touch-set. Recorded as `QB:deps/multidict-direct-import` in `quality-backlog.md`, keyed to
`roadmap.md` §RM-004 (the same owner that already holds `QB:deps/aiohttp-unpinned`), with the
0.01% both-parts test written out: `pip install buster-ripper` cannot pull aiohttp without
multidict, so the import cannot fail in a working install, and if it ever did the process dies at
import time — loudly, not silently.

T012 - serve_buster_ripper.sh forwards every environment value as exactly ONE argv word
captured 2026-10-05 on bash 3.2.57(1)-release (arm64-apple-darwin25), which is the interpreter
this script's `/usr/bin/env bash` shebang resolves to here - the version the empty-array
question had to be settled on rather than assumed.

Mechanism: a PATH shim named buster-ripper records the argv the wrapper execs (NUL-separated,
rendered with Python repr so whitespace and control characters stay visible inside one line).
No server starts, no port is bound, no upstream is contacted; HOME is pinned to a never-created
path. `argc` is the binary's real argument count; each bracketed entry is one argv word.

== the assembly, before -> after. Line 28's default form, every guard condition, header
   line 14 and README.md are unchanged; only the appends and the exec expansion move. ==
  before: EXTRA_FLAGS=""
          [[ -n "${DUMP_DIR}"    ]] && EXTRA_FLAGS="${EXTRA_FLAGS} --dump-dir ${DUMP_DIR}"
          [[ -n "${DUMP_FORMAT}" ]] && EXTRA_FLAGS="${EXTRA_FLAGS} --dump-format ${DUMP_FORMAT}"
          exec buster-ripper ... ${EXTRA_FLAGS}
  after:  EXTRA_FLAGS=()
          [[ -n "${DUMP_DIR}"    ]] && EXTRA_FLAGS+=(--dump-dir "${DUMP_DIR}")
          [[ -n "${DUMP_FORMAT}" ]] && EXTRA_FLAGS+=(--dump-format "${DUMP_FORMAT}")
          exec buster-ripper ... ${EXTRA_FLAGS[@]+"${EXTRA_FLAGS[@]}"}

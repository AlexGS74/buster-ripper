## Claim
In `buster_ripper/dump.py`, the collapsed branch's per-turn work writes no file and appends nothing to disk — `dump_turn`'s collapsed arms call `_append_record` only, which writes nothing; the only filesystem effect before a flush is the session-directory `mkdir` in `_lookup_or_create_state`.

## What it actually does
`dump_turn` sends `documented` to `_write_documented` (which writes `turn_000.json` / `turn_{N:03d}.diff` and appends `index.txt`), and sends both collapsed formats — `change-focused` and `self-contained` — to `_append_record`. `_append_record` appends the record to the in-memory `state.pending` list, adds `len(current_text.encode("utf-8"))` to `pending_bytes`, and calls `flush_all()` when `pending_bytes >= config.DUMP_FLUSH_BYTES`. The collapsed record builders (`_change_focused_record`, `_self_contained_record`, `_turn_zero_block`) and `_render_body` are pure string builders. Every artifact write lives in `_flush_state` (single `open("a")` write of the joined batch, then `pending.clear()`), reached only via a flush: `_append_record`'s threshold call, the `poll_flush` timer, or shutdown. The only filesystem effect on the collapsed per-turn path before a flush is `session_dir.mkdir(parents=True, exist_ok=True)` in `_lookup_or_create_state`, which runs only on first sight of a session. One precision: because the threshold flush is called synchronously inside `_append_record`, a collapsed `dump_turn` call that crosses `DUMP_FLUSH_BYTES` does write during that same call — that write is the flush the claim scopes out.

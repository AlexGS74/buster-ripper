## Composition

1. **Request path (producer).** `handle_messages` parses the body, normalizes it, computes `sid = session_id(body)` — sha256 over the system-prompt content alone, truncated to 12 hex chars (claim-11; `session.py` = `67a66b8a…`, live match). The request therefore always settles; a dump failure never fails it.
2. **Format resolution.** `dump_turn` first checks `DUMP_DIR` (ValueError guard), then `_resolve_format()` reads `config.DUMP_FORMAT` and raises `ValueError` for values outside `config.DUMP_FORMATS` = `("documented", "change-focused", "self-contained")` — closed set, all other package occurrences are reads (claim-171; `config.py` = `7e1eff53…`, live match). 3. **sid keying / pending buffer.** `_lookup_or_create_state` keys the module-level `_sessions` dict by sid, creating `DUMP_DIR/<sid>` (mkdir) and a `SessionState` holding `turn`/`prev_text`/`session_dir` plus `pending`/`pending_bytes`/`fmt` (claims 11, 12). `state.fmt = fmt` is refreshed each turn.
4. **Rendering.** `_render_body` emits only `[tools]`, `[system]` and one `[message i / role]` section per message in body order (claims 9, 10) — the arrival-order basis for diffs and records.
5. **Format dispatch (all three closed-union members).** `documented` → `_write_documented`: turn 0 via `_write_full_turn` (`turn_000.json`, `json.dumps(body, indent=2, ensure_ascii=False)` as UTF-8) then `turn_{N:03d}.diff` unified diffs for later turns, plus exactly one `index.txt` summary line per turn via `open("a")` (claims 87–90, 103); no pending records are added on this path (claim-122). `change-focused` → `_change_focused_record` and `self-contained` → `_self_contained_record`, both through `_append_record` (claim-103).
6. **Append-time sequencing.** `_append_record` computes `rendered_bytes = len(current_text.encode("utf-8"))` strictly before `state.pending.append(record)` (claim-116; live `dump.py:191-192`), increments `pending_bytes` by that rendered-text UTF-8 byte count — not record bytes (claims 117, 111, 112) — and calls `flush_all()` on the inclusive `pending_bytes >= config.DUMP_FLUSH_BYTES` (claim-110). The triggering record is therefore itself inside the batch its bytes trigger.
7. **Flush → artifact (consumer).** `flush_all` → `_flush_session` (empty-pending no-op; per-session exceptions logged, batch retained) → `_flush_state`: `state.fmt == "documented"` returns before resolving an artifact and without clearing pending (claim-121); a non-documented state with pending records resolves `_artifact_path` = `session_dir / f"{fmt}.log"` (claim-105), enforces the regular-non-symlink target guard, and makes exactly one `f.write("\n\n".join(state.pending) + "\n")` through `path.open("a", encoding="utf-8")` (claim-120), appending in arrival order with file creation handled by append mode (claim-44). `pending`/`pending_bytes` are cleared only after the append context exits successfully (claim-94).
8. **State advance.** `state.prev_text = current_text; state.turn += 1` run only after the writer/appender returns (claim-8); any raise leaves the turn counter intact so the turn is retried.
9. **Readers.** No production code under `buster_ripper/` reads `index.txt`, `turn_000.json` or `turn_*.diff` (claim-106; the guard inspects metadata only). Every production artifact content write funnels into that gate: turn JSON/diffs via `write_text` → `self.open(mode="w", …)` (claims 106, 168 — venv CPython 3.13.8), index lines and flush batches via `Path.open("a")` (claims 90, 120; append/create semantics claim-44 — Homebrew CPython 3.14.7); no other content writer exists under the package (claim-86), `mkdir` is not a `Path.open` and outside-root opens are uncovered (claims 165, 172).

The current implementation has:
- **8% coverage** on `chat.py` (should be >80%)
- **16% coverage** on `messages.py` (should be >80%)
- **20% coverage** on `passthrough.py` (should be >80%)
- **28% TOTAL coverage** across ALL modified files

The route handlers ARE new/modified code. They changed from creating sessions per-request to using shared sessions. This is a BEHAVIOR change, requires behavioral tests.

### What is NOT a Unit Test

In `test_session_pooling.py`:
```python
def test_no_new_clientsession_in_routes():
    """Verify route files do not instantiate new ClientSession."""
    messages_source = Path(messages.__file__).read_text()
    assert "async with aiohttp.ClientSession" not in messages_source
```

This is a SOURCE VERIFICATION TEST, not a unit test. It checks the file's text, not code behavior. It does NOT verify:
- That the handler actually uses the session correctly
- That the session is shared across requests
- That behavior is correct under any conditions

### What Constitutes Proper Unit Tests

Behavioral unit tests would:
1. Mock the backend HTTP server using `mocker.patch` or aiohttp test utils
2. Make a request through `aiohttp.test_utils.make_mocked_request`
3. Verify the handler uses `request.app["session"]` (same object across requests)
4. Verify session is closed on cleanup
5. Test error cases (session None, closed, etc.)

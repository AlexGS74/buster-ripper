## Analysis of Fake Tests

### What Makes a Test "Fake"

A **fake test**:
- Mocks everything (session, request, response)
- Tests "mock was called" not "code does the right thing"
- Would pass even if actual code was broken
- Only verifies the mock configuration, not the code

A **real behavioral test**:
- Tests actual code paths with real inputs/outputs
- Uses mocks only for external dependencies (backend HTTP calls)
- Verifies the code under test behaves correctly
- Would fail if the actual code was broken

## What Real Behavioral Tests Look Like

For passthrough routes, a **real** test would:

1. **Actually start the aiohttp app** with real routes
2. **Make real HTTP calls** through the app's test client
3. **Verify the actual behavior** - request transformation, header filtering, response handling

**Example of what a real test should be:**
```python
import aiohttp
from aiohttp import web
from aiohttp.test_utils import TestClient, TestServer

async def test_passthrough_forwards_request_to_backend():
    """Verify passthrough actually forwards requests to backend."""
    # Create real app with real session
    app = create_app()

    # Use TestClient to make real HTTP calls
    async with TestClient(app) as client:
        # Make real request to passthrough endpoint
        response = await client.get('/api/passthrough/test',
                                    headers={"X-Forwarded": "value"})

        # Verify real behavior
        assert response.status == 200
        # Verify backend was called (could mock backend, not the handler)
```

For compaction, real tests already exist (the pure function tests).
